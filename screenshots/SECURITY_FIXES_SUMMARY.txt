CRITICAL SECURITY FIXES - COMPLETED

ISSUE: Arbitrary Code Execution via eval() in custom.py
-------------------------------------------------------
The custom comparator used eval() with a restricted namespace, which could be bypassed using
type introspection attacks like: type.__bases__[0].__subclasses__() to access subprocess.Popen

FIX APPLIED:
1. Replaced eval() sandbox with AST-based validation
2. Parse expressions into Abstract Syntax Tree
3. Walk AST and reject unsafe node types BEFORE execution
4. Block ALL dunder attribute access (prevents __bases__, __subclasses__, etc.)
5. Block dangerous builtins (getattr, exec, eval, compile, open, __import__)
6. Maximum expression nesting depth (20)
7. Empty __builtins__ dict (not just restricted)
8. Only explicitly whitelisted safe functions available
